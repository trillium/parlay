Add `parlay sweep`, the fleet closure sweep, and restore the `identity --register` worktree/project fields that made teardown's safety checks reachable (robots-6xq7).

**The missing collector.** Parlay had every piece of agent closure and nothing that put them together: `crew-state` already reports an agent's terminal state, `teardown` already does the safe destroy, and `supervise` is per-agent wake-on-status — not a sweeper. So agents finished, posted `done: PR <url>`, and waited forever. On the captain's box that accumulated 38 stale panes against 2 live orchestrators and 306 registry entries. Firstmate's idle>2h auto-close cannot reach them and never could: every firstmate shutdown path enumerates via `$STATE/*.meta`, and a parlay-spawned agent has no `.meta` — it is invisible to that watcher permanently.

`parlay sweep [--apply] [--agent <id>] [--all] [--force] [--interval <sec>] [--verbose]` walks every parlay agent store, reads each agent's crew-state, and tears down the ones that are provably finished — each through the same `teardown` chain, so a `done` agent whose worktree still holds uncommitted or unlanded work is refused there rather than forced. The default is a dry run. Every policy rule fails safe, and the pure `ClassifySweep` holds the line: the sweeping agent never sweeps itself; ids in `$PARLAY_STATE_HOME/sweep-keep` are never swept; `needs-decision`/`blocked`/`failed` are HELD for the captain (absorbing them would destroy the state he needs to read); an unknown state is HELD; and a `done` agent is only closed unattended when its store proves it is a per-task spawn (a bound `task:` or a recorded `worktree:`).

**The sibling defect that made a naive sweep dangerous.** `--worktree`/`--project` were dropped from `MemValueFlags` and from `--register`'s meta-field loop during the Go port (both are in `store.ts`'s `MEM_VALUE_FLAGS`). Since the arg parser dies with `EXIT_USAGE` on an unknown flag, every `parlay identity --register … --worktree <path> --project <path>` that `parlay-spawn` issues for a worktree agent exited 2 and wrote **no frontmatter at all** — and `parlay-spawn`'s `registerIdentity` swallows the exit code, so the agent launched looking fine with an empty launch spec. Downstream, `parlay teardown` read no worktree, deleted the store, and orphaned the worktree and any unpushed commits in it without ever running its git checks. Both fields are restored, pinned by a regression test.

That is also why `sweep` HOLDs any agent with no launch spec on disk even under `--all`: an empty spec cannot distinguish "no worktree" from "a worktree this CLI failed to record", which is exactly the case where teardown's git safety silently does not apply. `--force` is the deliberate override.
